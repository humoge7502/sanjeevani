# 0011 — Authentication is off by default; the token is authoritative when it is on

**Status:** Accepted
**Date:** 2026-10-25

## Context

The shipped API resolved the approver from a **request body field**:

```
POST /api/plans/PLAN-001/approve
{"actor_id": "meera.iyer", "rationale": "..."}
```

`resolve_actor()` mapped that string to a role from `config/scenarios.yaml`, and
there was no credential anywhere in the system. Anyone who could reach the port
could approve and execute a consequential recovery plan by naming a person. In a
CVSS framing that is an unauthenticated, remote, high-integrity-impact defect —
around 9.1 — and it was the most severe issue in the repository.

The counter-pressure is equally real. This is an **offline demo** whose value rests
on documented, byte-reproducible behaviour: a frozen clock, a deterministic ledger
hash chain, 159 backend tests, 2 Playwright specs and a container smoke test that
all drive the loop without credentials. Adding mandatory auth breaks every one of
them and, worse, changes the thing being demonstrated.

## Decision

**Add a real authentication, role and tenancy layer, and leave it DISABLED by
default.**

Enabled by `SANJEEVANI_AUTH_ENABLED=true` plus a `SANJEEVANI_JWT_SECRET` of at
least 32 bytes. When on:

| Property | Behaviour |
|---|---|
| Identity source | A verified HS256 JWT. Nothing in a request body can create a principal. |
| Approver | Taken **from the token**. A body `actor_id` that disagrees is refused with `403 ACTOR_MISMATCH`. |
| Role checked | The token's role, not the seeded roster's — so a roster edit cannot grant authority. |
| Read routes | Require a verified principal. |
| `POST /api/demo/reset` | Requires `admin`. It truncates the audit ledger. |
| Algorithm | Pinned to `["HS256"]`, so an `alg: none` token is refused. |
| Lifetime / audience / issuer | All enforced; `exp` is required rather than treated as "never expires". |
| Revocation | The account is re-checked on every request, so disabling an account takes effect immediately rather than when its token expires. |
| Password hashing | PBKDF2-HMAC-SHA256 from the standard library, with the iteration count stored in the hash. Constant-time comparison. |

Identity lives in `config/identity.yaml`, generated by `scripts/make_identity.py`.
The shipped roster uses **documented demo credentials** so a reviewer can sign in,
with a loud instruction to replace them.

## Why off by default is the right default, not a cop-out

A deployment that *thinks* it is authenticated and is not is worse than one that
refuses to boot. So the failure mode is engineered the other way round:

- Enabling auth with no secret, or with a weak one, is a **startup failure**.
- `/api/health` reports `security.auth_enabled` and
  `security.ephemeral_jwt_secret`, so the posture is observable rather than assumed.
- `/api/state` reports the calling principal, including
  `authenticated: false` on the demo path. The unauthenticated case is *labelled*,
  not hidden.
- Ephemeral secrets (random per process, invalidating tokens on restart) are opt-in
  and flagged.

## Alternatives considered

**Make authentication mandatory.** Rejected. It breaks the offline demo, both
Playwright specs, the container smoke test and the documented reproducibility
guarantee — to protect a process that binds `127.0.0.1` and talks to in-process
mocks. The correct scope for "auth off" is a laptop demo, and that is exactly what
the flag says.

**Keep `actor_id` as a fallback when a token is absent.** Rejected, and this is the
important one. A code path that accepts an unauthenticated actor is the original
bypass with extra steps; a caller would simply omit the token. The guard is a
hard requirement when auth is on.

**Put the roles in the JWT and trust the claim forever.** Rejected. The token says
who you *were*. `require_authenticated` re-reads the identity store on every
request, which is what makes revocation possible at all.

**A directory service / OIDC.** Not built, and stated. `resolve_actor` and the
`Principal` construction are the seams; a real deployment swaps the identity store
for OIDC and the file for a managed directory.

## Consequences

**Good.** The highest-severity defect is closed by construction rather than by
convention: the enforcement point is the route signature (`Depends(...)`), not a
line inside a handler that a future edit could drop. 57 new tests, 26 of them
adversarial.

**Bad, and admitted.** The identity file is a file. There is no rate limit on
`/api/auth/token` beyond the general write limiter, no account lockout, no MFA, no
key rotation, and no audit log of *successful* authentications (failures are
counted in `sanjeevani_auth_failures_total`). Every one of those is a production
requirement, not a demo one.

**Also bad.** Tenancy is a claim on the principal and is recorded on ledger records,
but the approval registry is still process-global with no tenant partition. Two
tenants in one process would share the registry; the ledger would distinguish them
and the registry would not. Stated, not hidden.

## Enforcement

- `tests/redteam/test_auth_bypass.py` — 30 adversarial tests: unauthenticated
  reads/approval/execution, forged signature, `alg: none`, expired token, role
  escalation, actor mismatch, non-admin reset, oversized body, approval flood,
  wildcard actor id, hostile request id.
- `tests/unit/test_security.py` — hashing, token settings, rate limiter, CSP,
  and the assertion that the role model agrees with the state machine's.
- `test_a24_demo_path_is_unchanged_when_auth_is_disabled` — the demo path must
  still work, and must report itself as unauthenticated.
